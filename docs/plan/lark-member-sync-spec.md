# 飞书用户与群成员增量维护

## 目标与事实

恢复入群用户资料和群成员关系的增量维护，让新人和回群用户可以被正常 @。成员事件此前已订阅但未注册处理器；出站花名册依赖 lark_user 与 lark_group_member 联查。

用户确认群成员列表当前只返回100人，生产只读预览也证实了这一限制。不能从名单缺席推断退群。用户进一步明确「存量修复可以不做，核心是增量」，本次移除手动修复入口和全量名单同步，不执行生产存量回填。

## 关键设计

- 真人入群事件使用 users[].user_id.union_id 和 users[].name 补齐缺失或空姓名的用户档案及群成员，不依赖群列表或通讯录范围。已有非空姓名保留，本次不承担全局改名同步。退群及撤销拉人事件记录离群，保留用户档案。
- 使用官方 header.create_time（SDK 展开后的 create_time，毫秒）和消息 message.create_time 维护事件顺序。仅较新的成员证据覆盖旧状态，相同毫秒时离群优先；未知用户先收到退群事件也保存离群记录，避免随后旧入群事件恢复身份。
- lark_group_member.updated_at 保存最近成员证据的 UTC 时间。旧值仅作为既有状态的保守时间界限，不宣称它是历史事件发生时间。已查生产列为 timestamp without time zone、时区 Etc/UTC、无业务触发器；读写显式 UTC 转换，移除实体误导性的自动更新时间声明。当前仓库其余访问方只读成员表；旧测试实现退出后再验收，不与旧写入者混用。
- 每条真实群消息都推进发送者的成员证据时间，包括资料完整且已在群的用户，防止晚到退群事件覆盖较新发言。已有档案直接复用，缺档才在群事务锁外单独查用户资料，返回后短事务复查并原子补缺，避免慢请求阻塞成员事件；资料查询失败仍保留已提交的群消息成员证据，记录失败并继续普通消息。旧消息不能恢复较新离群状态。私聊仅补档，机器人发送者跳过。
- 成员状态使用参数化条件 upsert。事件批量更新在同群跨进程事务锁内完成，档案按稳定顺序写入；保留管理员、群主和管理权限、头像及已有公共身份。
- 入站先决定泳道，只在最终接收侧维护资料和成员。成员事件交接原始载荷，保留真实事件时间；处理失败向入口抛出。已 ACK 的长连事件记录失败日志；泳道接收端返回失败。
- 缺档联系人查询复用现有 bot 客户端池，15秒总时限覆盖访问令牌与资料请求，取消真实底层 HTTP。数据库写事务设定锁等待、语句和空闲限制。不提取生产凭据。

## 调用方覆盖

webhook、长连和泳道交接的入群/退群/撤销拉人事件；普通群消息和私聊；出站花名册与 @ 渲染；已有 /bind 在群状态判定。原有消息公共身份和管理员判定在补档后重读。机器人入群不进行全量初始化。

## 数据与部署影响

不新增表或字段。不新增管理端点，不扫描历史消息，不回填线上数据。服务变更为 lark-service，同镜像 lark-outbound 同步更新。使用 coe-at-users 隔离库、dev bot 验证事件和真实联系人查询，不发送飞书消息。原临时 ppe 维护泳道及 gateway 规则已清理。生产合码发布遵守独立确认流程。

## Tasks

1. 成员增量维护：产出按事件时间更新的用户和成员存储；验收覆盖新入群、回群、退群、撤销拉人、乱序、重复、未知用户退群及权限保留。
2. 消息补齐与集成：产出群消息证据推进、缺档查询和泳道交接；验收覆盖私聊、机器人跳过、联系人失败后成员证据保留、当前消息姓名和真实 @ 渲染。
3. 验证与交付：产出测试、类型检查、外部评审及隔离泳道验证；验收证明确实不调用100人群成员列表、不误标其他成员、事件时间在真实数据库中按 UTC 保存。
