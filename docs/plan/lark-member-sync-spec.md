# 飞书成员资料同步与 @ 修复

## 目标与事实

恢复飞书用户资料与群成员维护，使已在群里的用户能被出站 @ 正确解析。
线上已确认：张若等用户资料存在但成员记录仍为已退群；部分真实发送者缺成员或用户资料。当前成员事件虽已订阅却未注册处理器，日志存在 `nobody handles event type im.chat.member.user.added_v1`。出站花名册依赖成员表与用户表联查。

## 范围

恢复成员加入、移除、撤销拉人和机器人入群时的成员同步；补齐消息发送者缺失的资料；提供指定 bot、指定群的受鉴权同步入口用于存量修复。出站 @ 匹配规则、人设与 agent-service 不变；不恢复无关的 reaction 等事件；不自动遍历所有生产群或修改用户权限。

## 关键设计

- 飞书当前群成员列表是成员状态的来源。成员事件触发查询当前完整名单，不直接将历史事件的加入/退出动作写为当前状态。
- 群成员 API 只返回真人。离群差集只适用于有真实 user 消息或本次成员 user 事件证明的真人 ID；已登记机器人和无法分类的历史成员行保持原状，不从真人名单推导机器人在场状态。完整分页成功后才提交同一群的真人成员快照和真实姓名。成员在列表中标为在群，原有成员不在列表中标为离群；查询失败、分页不完整或数据无效不允许将部分名单落为完整名单。
- 同一群的同步跨进程串行，包括查询与事务提交，防止较早快照晚提交覆盖新快照。API 失败回滚并可观察。
- 消息确定由本部署落库后、记录消息前发现真实发送者资料缺失或群成员缺失/已离群时复用当前名单同步，并重新读取真实姓名；投递到其他泳道的一侧不做这次同步。历史消息只触发当前状态核查，不作为在群证明。私聊仅补真实用户档案，不写群成员。历史发送者已不在当前名单且档案仍缺失时单独查询用户档案；无通讯录权限时记录未补齐并继续消息，不恢复其成员状态。
- 飞书 API 暂时失败时，普通消息继续现有处理并记录资料同步失败；直连成员事件已经 ACK，后续处理失败拒绝并留下包含 bot/chat 的日志，不依赖飞书重推；泳道接收端与管理入口返回非成功响应。指定群手动同步和后续缺失资料消息是补偿入口。
- 复用现有 bot 上下文及飞书客户端池；不从生产提取凭据。用户姓名更新保留现有管理员、群主管理员等权限字段，公共身份不重新分配。
- 存量修复仅针对本次已定位的群，先展示同步预览/差异再执行；实际数据写入和验证通过项目受控入口进行。

## 调用方覆盖

webhook 与长连的成员事件、机器人入群事件；普通群消息与私聊；泳道交接消息及直接接收的成员事件；手动指定群同步；出站花名册与 @ 渲染。消息只在投影选择本地处理后执行同步。成员事件使用已有群会话映射及 bot 绑定选择泳道，交接前只读；交接信封的追踪 ID 使用事件 ID 或新 UUID，不伪造公共消息。管理入口明确作用于请求到达的部署及指定 bot/chat。测试使用 dev bot，涉及数据写入使用 coe 隔离库。

## 数据和部署影响

不新增表或字段，更新 lark_user、lark_group_member 及已存在身份的姓名。服务变更为 lark-service，同镜像 lark-outbound 随部署更新。生产合码与发布遵循独立确认流程。飞书直连事件只有 prod 接收，因此泳道验证必须覆盖交接接收端与实际飞书查询，发布后仍需观察真实事件处理日志。

## T1 评审处理

Codex / reviewer：必改的真人分类、泳道归属、入口失败语义全部采纳，已写入关键设计。建议的历史缺档终态、分页边界、绑定命令回归全部采纳。分页按 has_more/page_token，不按人数终止，覆盖短页、重复游标和错误 ID 类型；验证 /bind 对回群/退群成员的权限判定。

## Tasks

1. 成员同步：产出可复用的当前成员名单同步能力；验收覆盖完整分页、重新入群、退群、失败回滚、并发与权限字段保留。
2. 入站集成：产出成员事件处理和消息缺失资料补齐；验收覆盖群聊/私聊、bot 发送者跳过、历史重放不恢复已退群身份，以及真实 @ 渲染。
3. 存量修复入口：产出有鉴权、明确 bot/chat 参数的预览与执行接口；验收覆盖鉴权、无效输入、API 失败、隔离泳道与同步前后差异。
4. 验证与交付：产出测试、类型检查、外部代码评审和泳道验证证据；验收确认新人/回群用户能被 @、真正退群者保持过滤，并列明生产修复状态。
