# world 写世界，而不是排事件

> 状态：**待确认。** 已过一轮 codex T1 评审，评审意见已并入本文。
> 原先三条阻塞项已在"三条边界"一节给出答案，等 bezhai 确认或推翻；确认后即可进入实施。

## 目标

让 world 从"每半小时交一条时间地点句子"的调度器，变成**持续书写这三个人所处的那个世界**的东西。

具体要成立的三件：

1. **真实世界的事实是每天故事的起点**，不是背景播报。今天真的下雨 → 学校决定取消军训 → 这一天的安排空出来了；今天这个城市真有漫展 → 世界这一侧准备好了它（时间、地点、谁会去、门口什么样）。
2. **世界里有什么，由 world 决定，不由代码决定。** 代码里不再有任何一条世界内容。
3. **世界会因为她们做过什么而改变。** 今天发生的事改写世界，明天的世界跟昨天不一样。

> 注：第 1 条原先写作"她会想去 → 她约人"。那已经越过了本文自己划的边界——她想不想去是她的事。改掉。

## 不做什么

- **不解决"这棵树怎么全面到达三个人"。** 这一期只管把世界写丰富、写对。但**不等于不验证**：见下方"最小闭环"。
- **不让她读文档。** `她不读文档` 是既定边界，地方的样子只以"走进去看到"的形式到达她。
- **不改她那几只手的语义。** 她说什么就是什么这件事，本期不动——但**事实冲突归谁裁定**已经定了，见"三条边界"第一条。
- **不做多副本。** 整个设计仍建立在 agent-service 单副本上。

### 最小闭环（本期必须验收）

丰富但谁也感知不到的世界，等于没写。所以尽管"全面感知"推迟，本期仍必须打通并验收**至少一条**完整链路：

> 世界发生了一个变化 → 三个人中至少有一个**有途径**感知到它 → 她怎么反应是她的事 → **这件事的后果留在世界里，下一轮仍然成立**

验收口径的两条纪律：

- **不以她配合与否判定成功。** 她可以无视、可以拒绝、可以敷衍——那是宪法保障的。要验的是"途径存在"和"后果留存"，不是"她照做了"。
- **后果必须跨轮存活。** 只在当轮被看见、下一轮就消失的，不算。

## 现状与根因

### 世界现在不是一个存在，是一条消息队列

不管天黑、下雨、快递到了还是有人说话，落进库里全是同一个结构：一句中文 + 谁 + 哪儿 + 何时 + 持续多久。没有第二种形状。所以世界能给她的全部，就是一串带时间地点的短句——**句子本身就是上限**，跟 world 想象力无关。

三个直接后果：

- **世界没有状态。** 真实天气一天广播一次，`lasts_until` 为空，不进"这儿正在发生什么"。九点钟走进阳台的人没有任何途径知道外面在下雨。

  > **取数时刻这一条已经不存在了。** 中间过程里它先从写死的 08:00 对齐到生活日边界（CST 04:00），暴露出真正的问题：天气是实时接口、系统里没有预报，所以对齐到几点她都得带着那一刻的实况过一整天——**调到几点都是错的**。
  >
  > 现在六个源是 world 自己的手，它想再看一次就再看一次，这个格子空了。**但"世界没有状态"这条根因仍在**：world 看到下雨之后，得把"外面在下雨"写成世界的一个持续状态，九点走进阳台的人才知道。那是 T5 的事，不是取数频率的事。
- **世界没有东西。** 伞、快递、冰箱里的牛肉只在被某句话提到的那一瞬间存在，没有地方住，没有下文，所以没有后果。
- **世界不能反驳她。** 她写下"我撑着伞走到超市挑了牛肉片"，这件事就成立了。没有任何东西有权说"不是这样"。

### world 为什么只产出无聊的东西

它每轮拿到的只有一份流水账——发生过什么。**谁在乎什么、谁在等什么、谁怕什么，一个字都没有。** 一个只能看见已发生、又必须交出"接下来发生点什么"的东西，只能写天气、写开花、写快递到了：永远成立，永远不会错，永远没有用。

而系统里唯一记着"她想要什么"的东西——她攒下的那些挂念——world 看不到。

### 真实数据这条腿只有 3/5 在工作

五个源里，节气读 `term` 而源返回 `solar_term`，新番读 `titles` 而源返回 `anime`——**从上线至今一次都没生效过**，无日志无报错，单测因为替身自己编了跟代码一致、跟真实源不一致的 key 而永远绿。`holiday_name` 也从未被读，她只知道"今天是法定节假日"，不知道是端午。

素材面本身也太窄：只有天气、日出、节气、节假日、新番。**漫展、演唱会、展览、新片上映——这个城市这几天有什么，一个源都没有。**

### 代码里存着世界内容（必须全部清除）

- 一张写死的作息表：八条固定钟点 + 固定句子 + 固定地名，每天原样投进三个人的感知流。prod 上从引擎上线起一天不落。它的注释自承目的是"让世界里一直有会到期的东西"——**这是喂给调度器的，不是喂给她的**。
- 工具参数说明里的地名举例。举例是她唯一见过的地名样本，会被逐字抄走，已经造成两起实测事故。
- 她写错地名时的 30 条上限，超过就静默沉默。（这个数同时是扫描量上限。持锁的是**她自己那条 moment 串行轴**，不是文档树——扫描慢只拖她自己下一次醒来，不阻塞别人；真正的硬顶是那条轴 900 秒封顶。）
- "这个家里住着谁"是代码常量，且被当成收件人白名单——**world 可以让许阿姨来敲门，而她物理上无法对许阿姨说话**。
- 这个世界在地球上的坐标写死在一个 tool 里。**而且这一条有人做过一半**：prod 的 Dynamic Config 里确实有一项世界坐标（2026-07-25 配的，值是同一个地方、精度更高），但**全仓没有任何代码读它**——只有两处注释拿它当一个正在工作的机制做论证。配置配了、代码没接、注释写得像已经接上了。

  > 中间过程里我把坐标接到了那个配置项上，被 bezhai 问掉：**那跟写死在代码里没有本质区别，只是换个地方放，而且等于运维定一次这家人就永远搬不了家。** 设计文档里"这家人在广州"本来就跟"绫奈初二"、"入夏了"并排，属于 world 写下来的东西。现在城市是工具参数，这两个配置项都不需要了。
- 她开始知道外面什么样的时刻（08:00）写死，连配置项都没有。
- 五个真实数据源的呈现模板写死在代码里，world 改不了这个世界的叙事口吻。

## 总体设计

### 循环

```
真实素材 + 已经写下的世界
        ↓  （每天一次）
    今天这一天的大纲
        ↓  （每小时一次）
  跟三个人真实做了什么对账 → 改写世界 → 兑现该兑现的
        ↓
   世界变了，明天从这里继续
```

- **每天一次：写大纲。** 拿今天的真实素材加上它自己写下的世界，写出今天这一天的走向。产物是**文档**，不是一串事件。
- **每小时一次：修补。** 拿过去这段时间三个人真实做了什么，跟大纲对账，改写世界，并兑现到期的安排。
- **事件是副产品，不是产品。**

### 计划与事实的时间契约

这一节是 codex T1 挑出来的缺口。缩短兑现窗口**只缩短风险时间，并不消除风险**：14:00 排出 14:50 的来访，14:10 前提变了，旧事件照样会发生（已排出的事撤不回、改不了、删不掉）。所以时间关系必须显式定义，不能靠"窗口短"糊过去。

必须回答并写进实现的：

1. **谁负责兑现晚上的事。** 每次修补都要对照**整份当前大纲**，而不是只看眼前这一小时——否则早上写的晚间安排没有任何一轮会兑现它。
2. **窗口内前提变了怎么办。** 事件已排出、尚未到点，而大纲改了。这一格必须有明确处理（承认它会发生并让世界接住，还是别的），不能是空白。
3. **漏跑与停机。** 部署会杀 Pod，修补会缺席若干轮。恢复后：过去那段时间的安排是补发、失效，还是重新判断？"只看过去一小时的行为"会不会漏掉停机期间她们做过的事？
4. **跨日。** 生活日边界是凌晨四点，跟自然日不同。大纲的有效期跟这条边界怎么对齐。
5. **未来计划不能被当成现状读。** `地方/<路径>.md` 的正文会在她走进去时**原样**进入她眼前。如果大纲把"晚上伞留在学校"写进地方文档，她下午进去就读到了。**计划和现状必须在树里可区分**，这是硬性要求，不是风格问题。

验收必须覆盖：晚间安排的兑现、窗口内前提变化、漏跑恢复、"文档已改但事件未排"这四种情况。

### 真实 / 虚构 / 未知 三者的边界

宪法要求她的生活锚定真实世界。但**真实素材进入输入 ≠ 产出为真**：一天取一次的天气，很容易被扩写成全天的事实；一个真实存在的漫展，很容易被附加上不存在的细节。那正是本次要修掉的病，必须防它换个地方复发。

实现前必须定清楚：

- 哪些是**真实事实**（来自数据源，world 无权改写、无权补细节）
- 哪些是**这个虚构世界自己的安排**（学校的决定、邻居的动作、家里的生活——world 全权负责）
- 哪些是**未知**（数据源没给的，不许编成确定的事实）
- 素材**缺失 / 过期 / 中途更新**时各自的约束

### 一条必须钉死的边界：大纲只写世界这一侧

大纲写的是**世界会怎么动**：今天下雨、学校取消军训、沈老师把展板搬去操场、许阿姨下午来敲门。

**但"不写她的动作"这条判据不够。** codex 指出："沈老师下午来找绫奈"可以成立——它保证的只是**老师这一侧的行动**。它不能保证绫奈在场、不能保证见面发生、不能保证绫奈答应任何要求、更不能规定绫奈的情绪。

所以边界按**可观察结果**划，而不是按句子里有没有出现她的名字：

| 大纲可以规定 | 大纲不可以规定 |
|---|---|
| 配角做了什么（沈老师带着展板去了教室） | 三个人做了什么 |
| 世界处于什么状态（下雨、停电、店关门） | 三个人在不在场、有没有碰上 |
| 东西在哪、发生了什么变化 | 三个人的反应、情绪、答应与否 |

因此每小时那次修补的方向是**拿她们真实做了什么去改世界**，不是拿大纲去纠正她们。绫奈一整天没碰那幅画，那不是"她没按大纲走"，是世界得接受这个事实——沈老师明天会问起，或者那件事就这么黄了。

### 为什么是文档树不是数据库

数据库的 schema 就是这个世界能存在什么的上限，而那个上限由开发者定。想让世界里多一种东西——一把伞、一份校历、一个约定、一个人——就得加表、改代码、发版。

树没有 schema。world 觉得该有校历就写校历，觉得那把伞该留在学校就写下来。**世界里有什么由它决定。**

推论：本 spec 不规定树的分支结构，也不新增任何"放某类东西"的表。凡是遇到"这个东西没地方放"的念头，答案都是树里就是地方。

### 多模型协作 / 对抗

单个模型连续写同一个世界会复读自己的套路、顺从自己上一轮的判断、不会推翻自己——现在产出的天气/开花/快递就是这个形状。

至少两种职责，用不同模型承担：

- **写的**：写大纲、做修补。
- **挑刺的**：读大纲，提出异议。

> 职责分开是确定的；**每种职责是不是一个独立的常驻 agent，是实现选择，本 spec 不锁定。**

挑刺的判据必须可判定，且**附证据**，不能只给一个结论：

1. **跟已经写下的世界矛盾**——必须指出相冲突的两份材料，以及各自的适用时间。否则正常的状态变化（东西被搬走了、店关门了）会被误判成矛盾。
2. **跟昨天是同一天的复读**——必须区分"合理的持续状态"（连着下三天雨是真的）和"没有依据的重复安排"。

> 原先还有第三条"这一天里有没有任何人会不舒服"。**删掉。** codex 指出它两头都不成立：指三个人就是提前规定她们的感受（违宪）；允许任意配角就退化成"随便加一个不高兴的人"即可达标，反而鼓励为凑指标制造冲突。

### 各角色对树的写入权限

"多个角色并发写树"是本 spec 早先**自己锁定的实现选择**，不是必然。挑刺的职责目前只需要读。

所以实现前先定清楚：哪些职责**写**树、哪些只**读**、彼此怎么交接、会不会重叠运行。

> 但这**不再是 T1 的前置**。写入安全本来就该有（现状是遗漏而非取舍），跟将来有几个角色写树无关；就算最终只有一个写者，"先读、中间被改、再依据旧内容写回"这条路径在单个模型自己身上也成立。

## 硬约束

### 文档树没有任何并发保护

五只文档工具全是直接读写文件，**没有锁、没有版本号、没有 CAS**。两个写者同改一份：整份重写会后写覆盖先写且无提示；改写是 read-modify-write 不校验版本，中间被覆盖就丢写入，**而且不报错**。

注意这只覆盖**写入安全**。跨文档互相矛盾、以及"文档说的"和"事件排的"不一致，是另外的问题，修掉这条并不解决它们。

### 已排出的事撤不回

没有取消、改期、删除。改时间等于换 id，账上只会多一条独立的事，旧的照常兑现。处理方式见"计划与事实的时间契约"。

### 新增常驻角色的隐性契约（七条，不做就静默出错）

1. 时间源的 payload 多一个必填字段 → 每一拍校验失败**直接杀 Pod**，编译期看不出来。
2. 新数据类没被 wiring 的 import 链拉到 → **静默不建表**，跑到真读写才炸。
3. 表名从类名派生，撞上库里还活着的旧表 → 整批迁移回滚、Pod 起不来，而**空库测试里看不见**。
4. prompt 变量名对不上 → **静默渲染成字面量**，无任何编译期校验；非 prod 泳道没有对应 label 会静默回落到 production 版本。
5. 工具漏进"素材"分类表 → 静默按"留着"保留四小时，只有各角色**自己写的**那条分类用例能发现。
6. 幂等要自己搭：时间锚不取整、id 不从内容派生或轮次 id 撞了，重放会写出两条看不出是重复的记录，而成本表撞了那一笔 token **一行日志都不留**地消失。
7. 上下文 key 是 `泳道:角色` 的扁平命名空间，新角色名字撞上某个 persona 或 world 就是**共用同一行上下文**。

### 成本形状

每轮 input 三到五万 token，output 中位数只有十几个——**成本几乎全在 input**。三个人一天合计两千五百万到三千四百万 input token。新增常驻角色按其轮次频率线性叠加。

有一条明显差异：world 走的那条线有 prompt cache 命中（每轮一万五到四万四），三个人走的那条 **cached 恒为 0**。新角色应优先走有 cache 的那条。

## 三条边界

这三条原先列为阻塞项。下面是答案和推导依据。它们不是从若干等价选项里挑的，是排除掉违反既有约束的之后剩下的。

### 一、事实冲突：谁也不改写谁

> **树是世界状态的唯一权威。她的叙述是她自己行动的唯一权威。她的叙述不改写世界状态。**

树里写着伞留在学校，她记下"撑着伞出门"——**两条都留着，都不改**。世界不纠正她（她不是 NPC），世界也不跟着她改（宁可不记不可记错）。

另外两种处理都已经被既有约束排除：

- 树赢、改写她的叙述 → 违反"她不是 NPC"（`MANIFESTO.md` §6）。
- 她赢、树跟着改 → 就是现在的行为。那样世界永远没有阻力，本 spec 的第三个目标静默落空。

**矛盾本身是世界里的一个事实，进下一轮的材料。** 下次有人去拿伞，伞在学校；沈老师明天可能问起。这就是"阻力"的全部含义——不是有人出来否定她，是世界不因为她说了就变。

实现上的硬性要求：修补那一轮**必须看得见**"她说的"和"树上写的"对不上，并且**被允许把这件事本身写下来**。看不见就等于第二种处理。

### 二、对第四个人说话：能开口做，对方回应不做

分两层，两个交付范围：

- **能向第四个人开口——本期做。** 现在的收件人白名单是硬编码的三个 persona id，它本身就是"代码里存着世界内容"的一种。world 可以让许阿姨来敲门，而她物理上无法回应，这是代码把世界弄坏了。见 T2c。
- **第四个人能回应——本期不做，而且不是靠新增常驻 agent 做。** 许阿姨的回应属于"配角做了什么"，按上方边界表格本来就归 world 写。路径是：她开口 → 落进世界 → 下一次修补时 world 决定许阿姨怎么反应 → 作为世界这一侧的事实写回。

不给第四个人开活 agent 的理由：一个常驻角色要背全部七条隐性契约，成本按轮次频率线性叠加，而这个世界里可能出现的"第四个人"数量没有上界。

### 三、挑刺的异议：不是门，是必须被处置的材料

> **异议不阻塞兑现，但必须进入下一次动笔的输入，且写的那一方必须对每条显式处置。**

- 挑刺产出附证据的异议列表。
- 写的那一方下次动笔时**必须**拿到这份列表，逐条给出处置：改了，或者不改 + 依据。
- **没处置的异议不消失**，继续留在输入里直到被处置。这是防"退化成写日志"的那一格。
- **挑刺本身失败（报错、超时、返回空）不阻塞流程**，大纲照常兑现。挑刺是提质量的，不是安全阀；让它成为阻塞点等于给世界加一个单点故障。

哪些必须在兑现前处理：

| 判据 | 兑现前必须处理吗 | 依据 |
|---|---|---|
| 跟已经写下的世界矛盾 | **必须** | 矛盾一旦兑现成事件就撤不回（见"已排出的事撤不回"）；事后无法补救 |
| 跟昨天是同一天的复读 | 不必 | 复读是无聊不是错误，代价是明天再改，可事后修正 |

## 任务清单

> 只写目标 + 产出 + 验收口径。实现细节在动手时基于实际改动生成。

**T1 · 文档树的写入安全**
目标：并发写同一棵树不丢写入、不静默覆盖。
产出：写入具备冲突检测；冲突时失败可见（能喂回模型重试），而不是悄悄丢失。
验收：除"两个写者同时写一份文档"外，必须覆盖**先读、其间被别人改、再依据旧内容写回**这条真实的模型工作路径。
设计（已定）：每份文档一把进程内锁让单次调用原子；整份重写覆盖已存在的文档时必须带上读到那一份的指纹，不带则拒绝并要求先读；`edit_document` 的唯一命中本身就是天然 CAS，保留。
前置：无。原先写的"先定清楚各职责读写权限"已作废——见下。

> 修正：本 spec 早先称 `documents.py` "刻意不用 `serial.hold`"。**查无实据**：该文件零处提到锁、并发、版本或 CAS，三个相关 commit 的 message 也没提。它唯一记在案的"刻意不要"是不绑轮次 context，那是另一件事。**锁的缺席是遗漏，不是有据可查的决定**，补它不需要先推翻任何论证，也不需要等"各角色写入权限"定下来。

**T2a · 清除代码里的世界内容**
目标：代码里不再有"这个世界是什么样"的断言。
产出：地名举例、地理坐标、看外面的时刻、数据源呈现模板，移除或迁出。
验收：逐条对照调研清单销账；新增守卫用例，且该用例的判定边界必须写清楚（什么算世界内容）。

> 地名举例的清单比原先记的多两处：`world.py` 里 `expect.place` 的举例（注释自承同一个坑），以及 `documents.py` 六处路径举例（举的既是路径形状也是世界内容）。后者落在 T1 改的同一个文件里，两边要对齐。

> **作息表从本任务移出。** 见 T2d。

**T2d · 拆掉写死的作息表（跟 T4/T5 一起做，不能提前）**
目标：代码里不再规定这个家几点吃饭、几点天黑。
**排序约束**：每 60 秒一拍的日历是全仓**唯一**的高频到期源；world 的 `expect` 是低频模型轮次，且"一轮什么都不做也正常"。先删作息表、后做大纲与修补，中间会有一段世界里什么都不到期的真空，而代码自己的注释和用例都点名这是会**静默**弄死实验的失败模式。所以这一条必须等 T4/T5 的到期能力落地后才拆。
已查：Dynamic Config 里**根本没有** `living_day_schedule` 这一项（prod 一共 14 个 key，没有它）。所以 prod 每天投的就是代码里那八条内置 fallback，"要调就去改 Dynamic Config"这句注释从写下那天起没被用过。拆的时候不用考虑"线上配了别的值"这种情况。

**T2b · 地名上限的去留**
目标：她写错地名时不再因为一个魔法数字撞上静默沉默。
产出：去掉该上限，或换成不靠固定数字的做法。
验收：**必须同时给出扫描耗时的实测**。影响半径比字面小——拖的是她自己那条 moment 轴，不阻塞别人也不阻塞 world 写树；但那条轴 900 秒封顶，真拖到就会把整轮掐断。而且这只手在她每次换地方的路径上，频率很高。
排序：跟在 T2a 之后，两者在同一组函数和同一组测试 fixture 上贴着。

**T2c · 居民名单不再当收件人白名单**
目标：她能对世界里存在的第四个人开口。
产出：收件人校验不再依赖硬编码的三人名单。
验收：她向一个 world 写出来的人说话不再抛错。
依赖："三条边界"第二条。本期只做"能开口"；"对方能回应"由 world 写成世界这一侧的事实，不新增活的角色。

**T3 · 真实素材面**
目标：让 world 自己能看见真实世界，并补上"这个城市这几天有什么"。
产出：六个真实数据源成为 world 自己的手（城市是参数）；新增活动类数据源；**删掉代码替它取数再广播的那一整层**。
验收：给出每个源的真实调用证据；**单测替身必须以真实返回为准，不得自造字段名**（那正是两个源恒不生效一年没人发现的原因）；工具参数描述里不得出现任何具体城市名做举例。

已查清的现状（影响做法）：原来素材被 `"，".join` 压成一句中文，落成一条 Happening 广播出去。那条广播同时是"第三方真的能决定字节"的唯一通道，正文过转义，有用例钉着。**改成工具之后上游字节先进工具返回、再由 world 决定写不写进世界，那条防护落在哪儿必须重新回答**，不允许因为那个文件被删就顺手把防护一起删掉。

**投递形状（已定）：不投。六个源成为 world 自己的手，代码不再替它取数。**

> **这一条是推翻重写的。** 本节原先写的是"保留投递路径，但投带标签的事实"，理由是"真实事实是每天故事的起点，做成工具就等于允许它不查"。按那个方案做了一版，然后被 bezhai 一句话问掉：**agent 自己查天气、查漫展，为啥一定要写死。**
>
> 我那条理由是**工程思维**——用强推消除不确定性，正是本项目明令禁止的形状。而且它治标不治本：只要是代码去取数，代码就必须知道查哪座城市、几点去查、取回来怎么呈现、一天取几次，于是四个写死接连长出来。**根子在"代码替它取数"这件事本身。**

改成 world 自己的手之后，四个写死同时消失：

| 原先必须写死的 | 为什么消失 |
|---|---|
| 这个世界在哪座城市 | 成为工具参数。它自己知道这家人住在哪——那是它写在世界里的 |
| 几点去看外面 | 它想什么时候看就什么时候看 |
| 五个句子呈现模板 | 它拿到的是原始事实，怎么讲是它那一轮的事 |
| 天气一天只取一次 | 它想再看一次就再看一次 |

连带：那两个恒不生效的 key（`term` / `titles`）**不是被修好，是不再存在**——中间那层读错 key 的代码没有了。

**已经明确接受的代价：它可能不查。** 不设计任何补偿机制——不"没查过就自动注入"、不"提醒它该查了"、不保留兜底广播。它不查就是不查。宪法要求她的生活锚定真实世界，但那要靠改它的输入达成（它现在不查的真正原因是被饿着，每轮输入才一千多 token），不靠替它查。

**她不给这几只手。** 她在世界里，天气该是她走到窗边感受到的，不是她查 API 查到的。world 是世界事实的唯一来源，它看到之后写进世界，她通过世界感知。

**T4 · 写大纲**
目标：每天一次，用真实素材加已写下的世界，写出今天这一天。
产出：产物是文档；按上方表格划的边界，只规定世界与配角这一侧。
验收：连续观察若干天，断言产出跟真实天气/日期/活动对得上；断言大纲不规定三个人的在场、反应与情绪；断言真实事实没有被扩写、没有被附加不存在的细节。
依赖："三条边界"第一条。

**T5 · 修补**
目标：每小时一次，对账、改写世界、兑现到期的安排。
产出：改写树 + 排出到期事件；方向是世界适应她们。**外加：把天气从"一天一条广播"改成世界的一个状态**（见"世界没有状态"那条的注）。
验收：覆盖"计划与事实的时间契约"里点名的四种情况；构造"她没按大纲走"的场景，断言世界改的是自己而不是纠正她。
依赖："三条边界"第一条。修补必须看得见"她说的"和"树上写的"对不上，看不见就等于世界默认认账。

**T6 · 挑刺**
目标：用另一个模型对大纲提出**附证据**的异议。
产出：按两条判据给出异议，每条都指明相冲突的材料及其适用时间。
验收：不能只证明"跑过一次"。必须证明那些**必须在兑现前处理**的异议确实在兑现前被处理了。
依赖："三条边界"第三条。

**T7 · world 看得见她们想要什么**
目标：world 的输入里有"谁在乎什么、在等什么"，不只是流水账。
产出：她们攒下的挂念进入 world 的视野。
验收：对比改动前后 world 的产出，断言出现了跟具体某个人的挂念相关的安排。

**T8 · 最小闭环**
目标：证明写丰富的世界真的到达了她们，并留下后果。
产出：打通并验收上方"最小闭环"那一条链路。
验收：世界的一个变化有途径被感知、后果跨轮存活；**不以她配合与否判定成功**。

## 为什么这么选

- **每天大纲 + 每小时修补**，而不是每天一次：一天一次太慢，三个人是活的，早上定的走向到中午就跟事实脱节了。
- **产物是文档而不是事件**：事件是世界被时间切开之后的样子，不是世界本身。先有世界，事件才长得出来。
- **多模型**：单个模型自我回流积累的是回声。
- **树而不是表**：表的 schema 由开发者定，等于每次世界想丰富一点都要先来求人。
